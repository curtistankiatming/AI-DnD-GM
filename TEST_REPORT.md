## What was exercised

Automated checks include inventory quantities and partial charges; buy/sell costs and stock; ownership allocation; item comparisons and two-handed restrictions; selected-owner upgrades; atomic crafting; storage; persistent merchants and bounded bargaining/barter; free/paid recovery; meaningful level rewards; first-advancement gating; all twelve specialization actions; companion orders/tactics/personal rewards; objectives and deadline consequences; repeat-reward prevention; retreat recovery; practice restoration; hidden-information omission; and real HTTP new/action/save/list/load/delete requests.

The randomized diagnostic checks used isolated fixtures at levels 1, 5 and 10. They verified finite, bounded HP/resources, nonnegative integer gold/stock/XP, valid charge counts, conserved gear ownership, and unchanged protected facts after rejection. **Starting a diagnostic fixture at level 10 is not counted as earning level 10.**

## Browser run details

An unseeded server supplied actual randomness. A public-view decision policy selected visible actions, which were executed by clicking the original UI controls, including target dialogs, development choices, town shops, upgrades, a road-merchant purchase, bargaining, a caravan favor and crafting. The policy neither read secret campaign definitions during decisions nor granted XP/items, edited state, forced rolls, or reloaded failed decisions. The recorded actions and HTTP results are included in the separate validation evidence archive.

The policy is automation, not an independent human participant. Read the paired balance report before interpreting completion percentages. A separate final UI check loaded the earned character, used Guardian in practice, verified restoration and checked desktop/mobile layout.

## Environment and limitations

Tests ran in an isolated Linux container with **Node.js 22.16.0** and Chromium through Python Playwright. The environment blocked normal Chromium navigation to localhost. Consequently the harness rendered the **original HTML/CSS/JavaScript** with `set_content` and forwarded its fetch calls to the **real local HTTP server** through a Python binding. A temporary localStorage shim was used because the harness page has no normal origin.

This verifies rendered controls and real server action handling, but does not establish ordinary browser-origin behavior, persistent browser localStorage, or a Windows launch. Windows BAT files were reviewed as text, not executed. The user’s PC folder was not connected or modified. No real AI model or user's local model configuration was tested; only the compatible adapter and deterministic fallback were checked. No internet/public-tunnel test was performed.

A sample of valid Story Engine V3 saves was checked. Arbitrarily modified, corrupt, incompatible or Bellfire Echoes saves are not guaranteed to migrate. Keep original backups. Gameplay remains an authored level-1–10 custom d20 campaign, not full official 5e or unlimited freeform play.

## Feasibility conclusions

The implemented level-1–10 scope is runnable and demonstrated through ordinary progression. Shops, gear, materials, party growth, preparation and outcomes are linked to actual rules. The level-30 and level-70 tiers are explicitly **future design milestones only**, with no playable campaigns or completed class paths claimed. See `FEASIBILITY.md` for design decisions and remaining risks.

## Reproduce locally

```text
npm test
npm run playtest
npm run fuzz
```

`PLAYTEST_RUNS=5` selects the recorded 270-campaign matrix. `FUZZ_CASES=240` and `FUZZ_STEPS=60` select the recorded 14,400-action diagnostic set. Source scripts are bundled and work without installing npm dependencies.
