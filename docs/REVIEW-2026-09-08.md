# Repository review — V4.0.1 reliability candidate

Date: 8 September 2026. Scope: `curtistankiatming/AI-DnD-GM` only.

## Source and change boundary

The live repository was inspected through its connected GitHub API. Both `master`
(the default) and `main` pointed at `6fb5807b54600bcef4318467b86290a9a74370d7`.
The complete working baseline was verified against Git tree
`93704034b8096a9d083261b36b5f29eecd58eb30`, including the repository README and
launcher edits. This is not an unverified older ZIP substituted for the live code.

This candidate is intended for a review branch and PR against `master`. It does
not merge changes, delete or rename either primary branch, alter repository
visibility/protection/licensing, publish a release, deploy, or touch real saves.
The repository was public and the two primary branches unprotected when inspected.

This is maintenance of the existing authored level-1–10 game. No new chapters,
level-30/70 content, global economy rebalance or new class specializations are
claimed. The existing level-10 trial and post-advancement adventure are preserved.

## Implemented fixes

| Finding | Change | Regression coverage |
| --- | --- | --- |
| Level 7 promised four Technique uses but granted three until level 8 | Capacity now follows levels 2/5/7/9: 2/3/4/5 uses, plus the existing Endurance choice | All six classes, Endurance, and loading a partially spent level-7 save |
| Combat narration could lead with an earlier story reward | Current combat events provide the resolved outcome in both fallback text and the optional model prompt | Stale reward excluded; current attack/objective and party events retained |
| Rejected narrative actions could still invoke the optional model | The resolved action status is passed to the narrator; rejected actions return deterministic feedback immediately | Zero mock model calls for rejection, one for a valid opening |
| Save names accepted Windows device names that cannot be ordinary save files | Shared portable slot validation for save/load/delete, including JSON suffix handling | Reserved names rejected before writing; normal save names retained |
| HTTP integration tests used the game's normal save location | Tests create and remove an OS-temporary save directory | Actual HTTP save/list/load/delete on isolated files |
| Hard-coded API version could diverge from package metadata | `/api/health` reads `package.json` | Version checked during server tests and UI smoke |
| Invalid input could produce unhelpful server failures | Object-only JSON, malformed-URL handling and bounded port/AI-timeout settings | Malformed inputs rejected; valid operations and subsequent health request still work |
| Cross-origin form-style writes were not explicitly guarded | Mutating APIs require the local browser origin when supplied; JSON required for POST | Allowed local JSON requests and rejected mismatched-origin/non-JSON requests |

The HTTP checks are defense in depth, **not authentication** or permission to
publish the server. It remains a trusted single-player application accepting
client-supplied state. Do not enable a public tunnel or forward its port.

## Repository improvements

- `npm run check`: syntax checks all application and test JavaScript.
- Portable explicit-file test runner instead of relying on shell glob expansion.
- `npm run validate`: syntax, unit/integration, campaign policies and state checks.
- Pull-request/push CI definition: Ubuntu and Windows, Node 22 and 24, plus a
  bounded whole-campaign/state-check job. Actions are pinned to verified commit
  SHAs; permissions are read-only, checkout credentials are not persisted, and no
  install, deployment or model account is required.
- `.node-version` selects Node 24; documented/launcher minimum is Node 22.
- `.gitattributes` establishes portable source and Windows launcher line endings.
- `AGENTS.md` and PR template document approval, temporary-save, deterministic
  rules, evidence and scope boundaries for future work.
- Original V4.0.0 test/balance reports are retained as historical evidence rather
  than silently relabelled as results of this patch.

Node release status was checked against the official release/EOL documentation:
https://nodejs.org/en/about/previous-releases and https://nodejs.org/en/about/eol.
Node 24 is the recommended LTS baseline; Node 22 remains supported. Node 18 and 20
are no longer supported baselines. The local measurements below use Node 22.16.0,
not an unexecuted claim of testing every supported runtime.

## Player-interface smoke test

Ordinary Chromium navigation to localhost was blocked by the environment's
administrator policy. That restriction was not disabled. Instead, an offline
harness rendered the original HTML, CSS and JavaScript, and forwarded explicit
API requests to the real isolated local server. Browser storage was a memory-only
harness substitute. This is weaker than the user's real Windows launch/browser.

The harness used normal visible controls to create a level-1 Fighter, reject an
unaffordable potion request without changing gold/inventory/location, buy an
advertised Medicinal Herbs offer, save, enter practice, target a protection order,
attack, end the turn, retreat and load the saved state. It confirmed file creation
in the temporary save directory and the restored currency/location. There were
no browser JavaScript errors and no horizontal overflow at 390 × 844 pixels.
The desktop viewport was 1440 × 1000. No XP or items were granted for this smoke.

This was not a new blind level-10 browser playthrough. The level-10 coverage above
comes from scripted campaigns. Real browser localStorage persistence, Windows
batch launcher execution and the user's real AI model were not tested locally.

## Remaining findings and recommended next work

1. **Companion recovery:** a controlled level-10 fixture confirmed Orin's short
   rest sets Second Wind to one use even when his level-derived capacity is three.
   A rest can therefore reduce an unspent resource. This is pre-existing and not
   fixed in this focused patch. Next gameplay change should centralize companion
   resource refresh and cover rest/level/save transitions together.
2. **Player pacing:** the authored regional investigation/approach/crisis pattern
   still repeats. Script completion cannot establish enjoyment, content variety,
   or an ideal reward cadence. A fresh observed player session remains valuable.
3. **Narrator quality:** current-result grounding is improved, but an actual model
   may still produce inaccurate prose. No factual-accuracy guarantee is implied.
4. **Primary branch ambiguity:** choose one canonical branch, then set appropriate
   protection after this workflow has actually run. No branch or protection
   changes were made on the user's behalf.
5. **Public/project policy:** visibility and the existing UNLICENSED package field
   are untouched. Do not choose a distribution license or move private assets
   into this public repository without a separate explicit decision.

## Acceptance recommendation

Review this as a bounded reliability patch, not a finished balance overhaul.
Require the PR checks to pass before merging. Retain save backups; old ordinary
V4 saves keep their identity/progress, and increasing Technique capacity on load
does not silently refill spent uses. Start a fresh campaign for gameplay pacing
assessment, but do not grind a real save merely to validate a regression fixture.
